# atelyx-plugin-index

Atelyx 插件市场索引仓库。Atelyx 内置市场从这里读取插件清单、自动聚合收录；本仓库公开可见。

## 如何上架你的插件

零申请、零审核，三步即可：

1. **写好插件**：仓库根放一份 `plugin.json`（反向域名 `id`、`name`、`version`、`apiVersion`、按平台的 `entry`）与插件入口。字段与能力声明见 Atelyx 的插件开发文档。
2. **发布 Release**：给仓库打一个 `vX.Y.Z` 形式的标签并发布 Release，把平台安装包挂成资产，文件名必须严格按 `<id>-<版本>-<平台>.zip`：
   - `com.example.echo-0.1.0-windows-x64.zip`
   - `com.example.echo-0.1.0-linux-x64.zip`

   包内根目录同样要有 `plugin.json` 与入口文件（宿主解压后按它安装）。
3. **打标签**：给仓库添加 GitHub topic：`atelyx-plugin`。

索引每 6 小时扫描一次带 `atelyx-plugin` topic 的仓库，校验通过后自动收录。收录后，所有 Atelyx 用户都能在内置市场中搜索并安装；用户点安装时，市场按已装版本与最新 Release 的标签比较决定「安装」还是「更新」。

## 收录校验

索引只做确定性校验，不做人工审核：

- 默认分支的 `plugin.json` 存在且合法：反向域名 id、名称与版本非空、`apiVersion` 与宿主协议版本一致、至少声明一个平台入口；
- 仓库最新 Release 挂着至少一个按约定命名的平台安装包（声明了某平台却缺对应包时，该平台的用户会看到「未挂本平台安装包」）；
- 清单的 `id` 与包名里的 `<id>` 一致——宿主安装时同样校验，不一致的包会被拒收，避免一份包覆盖另一个插件的目录与私有数据。

清单里可选写一个 `type`（如 `"type": "panel"` / `"type": "tableview"`）作为市场分类标签；简介取仓库描述。徽标按**仓库归属**判定：仓库 owner 在官方名单里的显示「官方」，其余条目不显示徽标；不按自报 id 授予。

索引扫描或取数暂时失败时沿用上一轮条目，不会让正常插件因为一次网络抖动从市场消失。

> 发布者对插件的质量、安全与合规负全部责任。插件是本地原生程序：它能读写文件、启动进程、访问网络，安装第三方插件前请确认来源可信。
